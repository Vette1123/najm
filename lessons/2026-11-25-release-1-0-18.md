# Release 1.0.18 prep: najm-release reads origin's tags

## What

Getting 1.0.18 ready (resize label, link previews, background blur, Noctty
main 358ce0f6a). `scripts/najm-release.ps1` now takes "latest release" from
origin's `v*` tags (`git ls-remote --tags --refs origin`), not from every
local tag. The changelog is `release-notes/1.0.18.md`.

## Mistakes

- The local repo held 39 bare `v1.3.*` tags, Noctty's, each an exact copy of
  its `upstream/v1.3.*` twin. They came from a fetch made before the
  `upstream` remote had `tagOpt = --no-tags` and the `upstream/*` tag map.
  The old `git tag -l "v*" --sort=-v:refname` read `v1.3.138` as Najm's
  latest release and would have refused 1.0.18 as "not newer". That was
  caught at prep time, not at tag time.
- My first draft of the notes said the size label "fades" and that screen
  readers "announce" the labels. The code hides the label after
  `resize-overlay-duration` (750 ms) with no fade, and no screen reader has
  been run against either label. Both lines were rewritten from the code.

## What worked

- Checking the new tag logic against the real remote before committing: the
  old logic picked v1.3.138 and the new one picks v1.0.17 out of origin's 18 tags.
- Running `najm-identity-check.ps1` during prep, while CI was still running.

## Rules

- A Najm release decision reads origin, never local tags: Noctty's tags can
  sit in `refs/tags/` locally.
- Each claim in the release notes is checked against the code that makes it
  true (durations, names, what was measured).
